# AgencyDesk design

**Tenant integrity.** Tenant-owned records carry `agency_id`. Composite foreign keys require a project's client, a task's project and its assignee, and each attachment, comment, or time entry to belong to the same tenant as its parent. These constraints reject invalid relationships even through SQL. Request-level isolation is enforced by the API. It resolves the actor from a hashed session token and joins project and task queries against that actor's tenant and role. The API returns 404 when a guessed ID is outside that scope.

**Client visibility.** A client session is scoped to one client within one agency. The project query requires that client ID and the task query adds the task visibility check. Search, filters, and counts build on those predicates. A file or comment must also be marked client-visible. Downloads and approvals verify the scoped parent and file together. Reports include only explicitly shared durations on visible tasks, with no time-entry notes. Read transactions use a consistent snapshot across parent and child queries.

**Identity.** `people.email` identifies a global credential. `memberships(agency_id, person_id)` holds the tenant-specific role and client association. Sign-in takes an agency slug and portal type, and the resulting session binds to that membership. The same password can open the Willow client portal and the Fieldwork admin workspace under different sessions.

**Invite and removal races.** A unique key on agency and normalized email makes resend an upsert. An acceptance locks the invite row, so a retry sees the committed result. The global email constraint also handles parallel invitations from different agencies. Existing identities must prove their password before gaining another membership. Project mutations take a project row lock and recheck access after acquiring it. Removing staff then clears only the assignee column through the composite foreign key, retaining tasks, comments, and logged time.
